## Rule (9)

- **16 KB page-aligned native libraries** _(enforced)_ — All native libraries are built 16 KB page aligned (Android 16 requirement, done with CameraX 1.4.2 in v1.9.0); any new native dependency has to keep that property.  
  refs: `commit:649b2e0`, `file:android/native-build/build.sh`
- **apkpush / two-device adb discipline** _(enforced)_ — apkpush installs with -r -g -t over the pinned debug key (no uninstall, no data wipe), reconnects to the last wireless-debugging address, and lists devices; two phones are often attached at once, so always pass -s for anything read back.  
  refs: `file:AGENTS.md`, `cli:apkpush`
- **JNI ↔ R8 keep rules** _(enforced)_ — Every Java type/method resolved by name from native code needs a -keep rule in android/app/proguard-rules.pro, in the same commit as the JNI change; -keep class X does not cover nested X$Y. v1.6.2 crashed in release because NativeLib$PreviewCallback had no rule while NativeLib$SliceCallback did. Verify with bundleRelease + a dex check, not only installDebug.  
  refs: `file:android/app/proguard-rules.pro`, `file:AGENTS.md`
- **Never say 'YE3D' in user-facing text** _(enforced)_ — 'YE3D' is the developer's private name for their printer and means nothing to users: say 'Centauri Carbon 2' or 'cloud printing' in release notes, store copy, and UI text.  
  refs: `file:AGENTS.md`, `file:store_listing/metadata.md`
- **Release notes cap is 500 characters** _(enforced)_ — Play rejects the whole commit above 500 characters (v1.9.0 failed at 970 and needed a 402-char rewrite). The short shipped text lives in store_listing/metadata.md per version; the long changelog goes on the GitHub release.  
  refs: `file:store_listing/metadata.md`, `file:AGENTS.md`
- **Play edits expire in about an hour** _(enforced)_ — A Play listing edit lives roughly an hour, so it must be built and edits().commit()ed in one sitting — v1.9.0 lost a day to an expired staged edit. The AAB path is safe because upload_play_internal.py commits the edit it opens.  
  refs: `file:AGENTS.md`, `file:store_listing/metadata.md`
- **Public mirror snapshot flow** _(enforced)_ — Publish by snapshotting main into the public repo as one squashed, named commit per release (never pushing private history), then tag there — the private repo has no GitHub Actions, so a tag on origin alone builds nothing.  
  refs: `file:AGENTS.md`, `branch:public-sync`, `url:https://github.com/yemyatthu1990/slicepilot-android-public`
- **Release checklist** _(enforced)_ — Bump versionCode/versionName → bundleRelease + extractReleaseNativeSymbolTables + mergeReleaseNativeDebugMetadata → upload with scripts/upload_play_internal.py including --mapping and --native-symbols → commit, tag, push tag to the public repo so CI produces artifacts → store listing edit committed in the same session.  
  refs: `file:AGENTS.md`, `file:scripts/upload_play_internal.py`
- **UI work needs a screenshot in the conversation** _(enforced)_ — adb screencap → pull → read the PNG so it renders in chat; a file path is not evidence. Getting onto a model needs Home → Local model (SAF) because adb VIEW intents land on Home; a ~770-byte cube 3MF is enough when the phone has no model.  
  refs: `file:AGENTS.md`
